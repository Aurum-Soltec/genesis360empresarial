# Product Patterns

## Pattern: What → Why → Next
Every primary page should answer:
1. what is happening;
2. why the Genesis thinks it matters;
3. what the manager can do next.

## Pattern: Progressive disclosure
Keep evidence, methodology, coverage and rule-version details accessible but secondary.

## Pattern: Confidence-aware UX
When confidence is low, recommend the smallest useful action to improve the analysis.

## Pattern: Empty state as next action
Do not say only “No data”.
Explain what creates the missing data and provide the next action when safe.

## Pattern: One dominant CTA
A screen may have secondary actions, but only one visually dominant action in the primary decision area.

## Pattern: No jargon-first
Use “Sua prioridade” before “Pain Finding”.
Use “Plano de decisão” before exposing “GDS” when the audience is not technical.
